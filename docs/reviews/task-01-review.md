# Task-01 코드 리뷰 결과

- **검토 대상:** `task-01.diff`, 구현 기준 v0.3 §3
- **검토 범위:** `src/core/config.ts`, `tests/config.test.ts`, `tsconfig.json`, 관련 프로젝트 설정 및 문서
- **보고된 검증 결과:** typecheck 0 errors / test 33 passed / build OK
- **리뷰 방식:** 제공된 diff 정적 검토. 코드 수정 없음. 테스트 재실행 없음.
- **발견 사항:** 총 6건 — High 1건, Med 4건, Low 1건

## 발견 사항

### 1 / High / diff 내 테스트 코드 구문 오류

**문제:** `tests/config.test.ts`에서 문자열의 닫는 따옴표가 누락된 것으로 보이는 부분이 6곳 존재한다.

**근거:** `tests/config.test.ts:286, 354, 362, 397, 401, 405`

```ts
describe("config ??3.1 ... , () => {
it("100BPM ??0.6珥?, () => {
```

제출된 diff 그대로라면 TypeScript 파싱에 실패할 것이므로 보고된 `typecheck 0 errors / 33 passed / build OK`와 일치하지 않는다. diff 생성·전달 과정에서 텍스트가 손상되었을 가능성도 있다.

**권장 조치:** 실제 저장소 파일과 제출된 diff를 대조하고, 원본 파일 기준으로 typecheck·테스트·빌드 결과를 재확인한다.

### 2 / Med / 판정 테스트가 실제 판정 로직을 검증하지 않음

**문제:** 명세 3.5의 Perfect/Good/Miss 테스트가 상수와 경계값 비교에 머물러 있다.

**근거:** `tests/config.test.ts:319–349`

```ts
expect(90 <= PERFECT_WINDOW_MS[100]).toBe(true);
expect(91 > PERFECT_WINDOW_MS[100]).toBe(true);
```

이 테스트는 윈도우 상수 값은 검증하지만, 실제 판정 함수의 Perfect 우선 처리, 음수 방향 판정, 입력 시각 보정, 경계값 처리 오류는 검출할 수 없다.

**권장 조치:** 실제 판정 함수 구현 시 BPM별 양·음수 경계, Perfect 우선순위, Good 초과 Miss를 입력-결과 기반 테스트로 검증한다.

### 3 / Med / 명세 3.5 주요 상태 전이 테스트 누락

**문제:** 일부 테스트 벡터가 헬퍼 함수 검증으로만 대체되어 실제 전투 규칙이 검증되지 않는다.

**근거:** `tests/config.test.ts:428–461` 및 테스트 파일 전체.

검증되지 않은 대표 항목:
- 동일 비트에서 Miss 이후 Perfect 재입력 시 `duplicate_ignored` 처리
- 템포 예약 후 기존 BPM 유지, 예약 경계 적용, 적용 시 콤보 초기화
- 회피 Perfect/Good/미입력에 따른 HP 처리
- 최대 120비트 경과 시 `timeout` 패배

예를 들어 `nextBarBoundary(6) === 8`은 경계 계산만 검증하며 beat 8에서 실제 BPM이 바뀌는지는 검증하지 않는다.

**권장 조치:** 후속 전투 로직 구현 시 상태 전이, 이벤트 순서 독립성, 타임아웃을 별도 테스트로 검증한다. 현재의 33개 테스트 통과를 명세 3.5 전체 검증으로 해석하지 않는다.

### 4 / Med / TypeScript 검사에서 Vite 설정 파일 제외

**문제:** `strict`는 활성화되어 있으나 `tsconfig.json`의 `include` 범위가 `src`, `tests`로 제한되어 있다.

**근거:** `tsconfig.json:479, 486`

```json
"strict": true,
"include": ["src", "tests"]
```

`vite.config.ts`는 현재 `tsc --noEmit`의 검사 대상에 포함되지 않는다. 또한 `vite.config.ts`가 `vite`의 `defineConfig`를 사용하면서 `test` 속성을 선언하고 있어 설정 파일을 검사할 경우 타입 호환성 문제 가능성이 있다.

**권장 조치:** 설정 파일을 포함한 타입 검사 범위를 점검하고 Vite/Vitest 설정 타입의 호환성을 검증한다.

### 5 / Med / 시간·비트 헬퍼 함수의 입력 유효성 보장 부재

**문제:** 변환 공식 자체는 맞지만 함수가 유효하지 않은 입력을 제한하지 않는다.

**근거:** `src/core/config.ts:203–205, 210–212, 219–221`

```ts
export function beatDurationSec(bpm: number): number {
  return 60 / bpm;
}
```

`beatDurationSec(0)`은 `Infinity`, 음수 BPM은 음수 시간을 반환한다. `isEnemyAttackBeat(4.5)` 및 `nextBarBoundary(-1)` 역시 0-based 정수 비트라는 명세 전제에 맞지 않는다. 호출 측에서 유효성을 보장한다면 실행 중 문제가 발생하지 않을 수 있다.

**권장 조치:** 호출 측과 함수 내부 중 어디서 BPM·비트 번호 유효성을 보장할지 결정한다. 명세에 없는 예외 동작은 임의로 추가하지 말고 `docs/decisions.md`에 제안·승인 후 적용한다.

### 6 / Low / diff 내 한글 인코딩 손상

**문제:** 주석, 테스트 설명, 리뷰 로그의 한글이 깨져 있다.

**근거:** `src/core/config.ts:100–102`, `tests/config.test.ts:251–254`, `docs/review-log.md:33–45` 등.

`?쒖뒪??`, `洹쒖튃` 같은 문자열이 포함되어 있어 가독성과 유지보수성이 저하된다. 1번의 구문 오류와 같은 전달 과정 손상에서 비롯되었을 수도 있다.

**권장 조치:** 실제 저장소 원본에서 재현되는지 확인하고, UTF-8을 유지하며 diff를 다시 생성한다.

## 중점 확인 결과

| 항목 | 결과 | 근거 및 해석 |
|---|---|---|
| `config.ts` 수치 상수 | 일치 | 명세 §3.1–3.3에 제시된 수치값과 일치 |
| 명세에 없는 수치 상수 | 발견되지 않음 | 추가로 정의된 임의 수치 상수 없음 |
| ms/초 단위 혼동 | 발견되지 않음 | 윈도우·캘리브레이션은 ms, 박자 길이는 `60 / BPM`초 |
| BPM/박자 간격 | 정상 | `beatDurationSec`의 정상 BPM 계산 정확 |
| `tsconfig` strict | 활성화 | `strict: true`, 단 설정 파일 검사 범위 제한 |
| 테스트 실효성 | 부분 충족 | 상수·헬퍼 검증은 있으나 판정·상태 전이 미검증 |
| 보고된 테스트 실행 결과 | 재확인 필요 | 제출된 diff의 구문 오류와 성공 보고 불일치 |

## 최종 판단

**수치 설정 및 기초 헬퍼 함수는 명세의 값과 부합하나, 제출된 diff 그대로는 승인하기 어렵다.**

권장 확인 순서는 **① 구문 오류 및 테스트 결과 불일치 → ② 설정 파일 타입 검사 범위 → ③ 실제 판정·상태 전이 테스트 계획**이다.

단, Task-01이 초기 프로젝트 구성과 상수 정의 단계라면 후속 전투 로직이 아직 없는 것은 곧바로 구현 결함을 뜻하지 않는다. 2번과 3번은 후속 태스크에서 반드시 확인할 검증 공백이다.

> 이 문서는 제공된 diff의 정적 리뷰 결과다. 코드 수정이나 테스트 재실행은 하지 않았다.
