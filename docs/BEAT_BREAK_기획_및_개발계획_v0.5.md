## 1. 한 줄 소개
박자를 맞춰 콤보를 쌓은 뒤 **플레이어가 직접 BPM을 높여** 더 강한 공격을 노리는 리듬 액션 게임. BPM이 높아질수록 보상은 커지고 타이밍 판정은 어려워진다.

## 2. 문제 정의와 핵심 가설
- **차별화 질문:** 플레이어가 직접 위험도를 조절하는 템포 선택이 리듬 전투의 재미를 높이는가?
- **H1 자발적 선택:** 템포 업이 강요되지 않아도 플레이어가 보상을 기대하며 템포 업을 선택한다.
- **H2 위험·보상:** 높은 BPM은 더 높은 보상을 주는 동시에 정박 성공률을 낮춘다.
- **H3 이해 가능성:** 처음 플레이하는 사람이 짧은 안내를 보고 30초 이내 정박 공격에 성공한다.
- **H4 재도전:** 한 판 종료 후 재도전 의향이 나타난다. 영구 강화의 영향은 별도 실험 전에는 주장하지 않는다.

## 3. 핵심 규칙 — 구현 기준 v0.5 (검증 전 가정)

**수치나 규칙을 Claude Code가 임의로 변경하지 않는다. 변경 제안은 `docs/decisions.md`에 기록하고 사람의 승인을 받은 후 적용한다.** 이 문서의 구현 기준은 웹 MVP용이며, 테스트 데이터가 생기면 개정할 수 있다.

### 3.1 시간과 판정
- 4/4박자, **1마디 = 4박**. 내부 비트 번호는 `0, 1, 2, ...`의 0-based 정수. `beat 0`은 전투 시작 기준 시점.
- 초기 BPM **100**, 템포 단계 **100 → 120 → 140**, 최대 140. 템포 하강 **없음**.
- 각 BPM의 1박 길이: `60 / BPM`초. Perfect 윈도우: 100/120/140 BPM에서 각각 **±90/±75/±60ms**. Good: **±160/±135/±110ms**. 경계값 포함(`<=`). Perfect 우선.
- 입력은 입력의 *보정된 시각*에서 **가장 가까운 비트**에 배정한다. 정확히 중간이면 **이전 비트**에 배정한다. 해당 비트의 Good 범위를 벗어나면 Miss.
- **한 박자에 행동은 하나.** 비트마다 첫 입력(공격·회피 무관) 1회만 처리한다. **Miss도 그 비트의 기회를 소모**한다. 이후 입력은 공격·회피 모두 `duplicate_ignored`로 기록하되 판정/콤보/피해를 변경하지 않는다. (D-10)
- 공격 입력을 하지 않은 비트는 **콤보를 유지하고 아무 효과도 주지 않는다**(미입력에 대한 자동 Miss 없음). 본 규칙이 연타 억제와 맞는지는 테스트 때 검토.
- 모든 판정은 프레임 업데이트 횟수가 아닌 절대적인 비트 시각을 기준으로 한다. `AudioContext.currentTime`을 시간 기준으로 사용하되 입력 타임스탬프의 시간축 정렬과 사용자 캘리브레이션을 별도 처리한다.
- MVP의 캘리브레이션 오프셋 초기값은 **0ms**, 사용자 설정 가능 범위는 **-200~+200ms**, **10ms 단위**. 보정된 입력시각 = 시간축 정렬된 입력시각 + 캘리브레이션 오프셋. 부호 의미를 UI에 표시한다.

### 3.2 콤보·템포 변경
- Perfect/Good 공격 시 콤보 +1, Miss 시 0. **템포 업 선택 가능 조건은 콤보 5 이상**.
- 템포 업은 별도 버튼으로 요청한다. 조건 충족 시 **다음 4박 마디 경계**에 변경을 예약한다. 예: beat 6에서 요청하면 beat 8부터 변경. 현재 마디가 아닌 다음 경계만 허용한다.
- 템포 변경은 최대 한 건만 예약. 동일한 변경 대기 중 추가 요청은 무시한다. 최대 BPM에서는 요청 불가.
- **템포 변경이 실제 적용되는 순간** 콤보 0, 그 전까지는 기존 BPM·판정·피해량을 유지한다. 적용 시 비트 번호는 연속되고 시간표만 새 BPM에 따라 이어진다. 음향도 동일한 경계에서 전환한다.
- 템포를 올리지 않은 플레이어에 대한 콤보 추가 보상은 MVP에서 **없음**. 오래 유지할 때 지루한지 **H1 관찰 항목**으로 남긴다. BPM 하강은 MVP에서 구현하지 않는다.

### 3.3 공격·적·승패
- 플레이어 HP **5**, 적 HP **300**. 양쪽 HP는 0 아래로 내려가지 않도록 제한한다.
- 기본 공격 피해 **10** × BPM 배율(100/120/140에서 **1.00/1.25/1.50**) × 타이밍 배율(Perfect **1.25**, Good **1.00**, Miss **0**). **소수 피해 허용**하며 UI에서는 소수 첫째 자리까지 표기한다.
- 적 1종, 단일 전투 아레나. 적은 **beat 7, 11, 15, ...**(4k+3, k≥1 — 각 마디의 마지막 박, 첫 마디는 적응 구간)에서 1HP 피해의 공격을 시도한다. (D-09) 해당 비트의 공격은 시작 전에 경고 표시한다(전 비트부터 시각 알림).
- 플레이어 **회피 버튼은 적 공격 비트에만 성공**하며, 해당 비트 **Perfect 판정 윈도우 이내**여야 한다. 성공하면 해당 적 공격을 무효화한다. Good/Miss 회피는 피해를 막지 못한다. 회피를 시도하지 않아도 피해를 받는다.
- 적 공격 비트(beat 7, 11, 15, ...)는 회피 전용 비트다. 이 비트의 첫 입력이 공격이면 `attack_ignored_dodge_beat`로 기록하고 **회피 기회를 소모**한다(피해 1). 회피 성공(Perfect) 시 콤보 유지. 회피 실패/미입력 시 피해 1, 콤보 유지. 일반 비트의 첫 입력이 회피면 효과 없이 **공격 기회를 소모**한다(콤보 유지, 피해 없음). (D-01, D-10)
- 피해 적용 순서: 적 공격 비트 → 회피 판정 → 피격 → 플레이어 HP 검사. 일반 비트 → 공격 판정 → 적 HP 검사.
- 적 HP 0이면 **승리**, 플레이어 HP 0이면 **패배**. 승패가 확정되면 입력·비트 진행에 따른 전투 상태 변경을 중지한다. 결과 화면에서 재시작 가능.
- 공격/회피와 적의 타격 판정은 입력/비트 이벤트 도착 순서에 따라 달라지면 안 되므로 **해당 비트 판정 윈도우가 닫힌 뒤 한꺼번에 확정**한다. 단, 같은 비트 안의 입력끼리는 **먼저 도착한 입력 하나만** 유효하다(D-10). 시각적 피드백은 즉시 보여줄 수 있지만 최종 HP 판정은 창 마감 후 확정한다.
- 한 판은 **최대 120비트**로 제한하고, 그때까지 승패가 결정되지 않으면 **시간 초과 패배** 처리한다. 테스트 로그에 별도 `timeout` 원인을 기록한다.

### 3.4 이번 MVP에서 제외
- 위치 이동, 방 3개, 적 2종, 보스, 로그라이트 강화·영구 강화는 **확장 목표**이며 11월 24일 전 필수 아님.
- H4는 강화 시스템의 효력이 아닌 **재시작 선택과 재도전 의향**만 관찰한다.

### 3.5 미리 확인할 반례와 테스트 벡터
- 100BPM beat 0 기준 +90ms → Perfect / +91ms → Good / +160ms → Good / +161ms → Miss.
- 120BPM 기준 +75ms → Perfect / +76ms → Good / +135ms → Good / +136ms → Miss.
- 140BPM 기준 +60ms → Perfect / +61ms → Good / +110ms → Good / +111ms → Miss.
- 동일 비트에서 첫 Miss 후 Perfect 재입력 → 첫 Miss만 유효, 두 번째는 `duplicate_ignored`.
- beat 6 템포 업 예약 → beat 7까지 기존 BPM 유지 → beat 8에서 새 BPM 적용 및 콤보 0.
- beat 7에 회피 Perfect → 피해 0; beat 7에 회피 Good 또는 미회피 → 피해 1. (v0.4, D-09)
- 최대 120비트까지 적을 처치하지 못하면 `timeout` 패배.

## 4. 평가 지표와 방법
| 가설 | 기록할 지표 | 확인 방법 | 판단 주의 |
|---|---|---|---|
| H1 | 템포 업 가능 횟수 대비 선택 횟수, 최고 BPM | 이벤트 로그 | 선택 자체가 즐거움의 증거는 아니므로 인터뷰 병행 |
| H2 | BPM별 Perfect/Good/Miss 비율, 피해량, 피격률 | Vitest 로직 테스트 + 플레이 로그 + 간단 시뮬레이션 | 성공률 60~80%는 임시 관찰 구간이며 합격선으로 단정하지 않음 |
| H3 | 첫 정박 성공까지 걸린 시간, 규칙 설명 요청 여부 | 신규 테스터 관찰 | 표본이 적다면 일반화 금지 |
| H4 | 재시작 선택 및 '한 판 더?' 5점 응답 | 플레이 후 간단 질문 | 영구 강화 효과와 혼동하지 않음 |

**핵심 구분:** Vitest는 규칙의 정확성을 검증한다. 재미는 직접 플레이 및 다른 사람의 피드백으로 검증한다.

## 5. 개발 아키텍처
- 웹: Vite + TypeScript + Phaser 3 + Vitest.
- 순수 모듈: `BeatTimeline`, `RhythmJudge`, `ComboSystem`, `TempoSystem`, `CombatSystem`, `RunTelemetry`.
- 오디오 시계: `AudioContext.currentTime` 기준으로 미래 박자 시각을 스케줄링. `setTimeout`은 재생 준비를 위한 보조 스케줄러로만 사용하며, 판정 기준 시각으로 사용하지 않음.
- 사용자 입력: 고해상도 입력 타임스탬프를 오디오 시계와 일관된 시간축으로 변환하고, 캘리브레이션 오프셋을 적용. 오디오 출력 지연과 입력 지연은 별개의 원인일 수 있으므로 기기별 보정값 측정.
- BPM 변경: 즉흥적인 현재 비트 변경이 아니라 **다음 마디 경계**에 반영하도록 설계. 변경 시 다음 비트 시각을 일관되게 재계산하고 중복 판정을 방지.
- 테스트: 시간·난수 의존성 주입, 경계값, BPM 전환, 중복 입력, 콤보 리셋, 피해 계산 테스트.
- UE5: 웹에서 검증한 **규칙만** C++로 재구현. Quartz를 리듬 이벤트/오디오 동기화의 후보로 사용하되, 입력 타임스탬프와 시계 정렬을 별도로 확인. 에디터에서 핵심 전투 1개 구현.

4. Vitest/수동 플레이: 객관적 기능 검증과 주관적 재미 평가를 분리한다.
5. 사람: 반영/보류/기각을 결정하고 `docs/decisions.md`에 기록한다.

**정직성 원칙:** AI가 일부러 잘못된 코드를 만들었다는 사례를 꾸미지 않는다. 실제 발견한 문제와 테스트 결과만 자기소개서에 작성한다.
