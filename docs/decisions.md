# BEAT//BREAK — 의사결정 기록

형식: 결정 / 근거 / 변경 조건. 규칙 수치·기획 변경만 기록한다(버그 수정은 `review-log.md`).

## D-01 적 공격 비트는 회피 전용 (2026-11-16)
- **결정:** 적 공격 비트(beat 4, 8, 12, ...)에서는 공격 입력을 무시하고 회피만 처리한다. 회피 성공(Perfect) 시 콤보 유지, 회피 실패(Good/Miss/미입력) 시 피해 1, 콤보는 유지한다.
- **근거:** v0.3 3.3절의 41행(둘 다 입력 시 회피 우선)과 42행(공격은 적 공격이 없는 비트에서만 처리)이 충돌. "공격 비트 / 회피 비트"로 역할을 나누는 쪽이 규칙 설명이 단순해 H3(이해 가능성)에 유리하다고 판단.
- **변경 조건:** 플레이테스트에서 회피 비트를 "쉬는 박자"로 느껴 긴장감이 떨어진다는 피드백이 2명 이상이면 재검토.
- **미결:** 회피 실패 시 콤보 리셋 여부 → MVP는 유지. H2 관찰 후 결정.

## D-02 밸런스 사전 예측 (2026-11-16)
- **예측 1 — 전투가 짧다:** 적 HP 300 ÷ 100 BPM Perfect 피해 12.5 = 24타. 회피 비트 포함 약 32비트(약 20초)에 전투 종료. 템포 업 기회가 1~2회뿐이라 H1(자발적 선택) 관찰이 어려울 수 있음.
- **예측 2 — 초보자가 먼저 패배:** 플레이어 HP 5, 4비트마다 적 공격 → 회피 전부 실패 시 20비트(100 BPM 약 12초)에 패배. H3 "30초 이내 첫 정박 성공"보다 패배가 먼저 올 수 있음.
- **검증 방법:** 11/19 시뮬레이션 + 플레이테스트(전투 시간, 패배 시점, 템포 업 횟수).
- **수정 후보:** (a) 적 HP 600 (b) 적 공격을 beat 16부터 시작(첫 4마디 연습 구간) (c) 둘 다.
- **지금 수정하지 않는 이유:** 예측을 데이터로 확인한 뒤 바꿔야 변경 근거가 생긴다.

## D-03 Bpm 유니온 타입과 비트 번호 검증 범위 (2026-11-16)
- **결정:** BPM은 `type Bpm = 100 | 120 | 140`으로 타입 제한. 비트 번호 검증은 BeatTimeline 진입점에서만.
- **근거:** 명세에 없는 오류 처리 규칙을 만들지 않고 타입으로 잘못된 입력 차단 (리뷰 #5)
- **변경 조건:** BPM 단계가 추가되면 유니온 타입 확장

## D-04 nearestBeat 중간값 판정: 이전 비트 선택 (2026-11-16)
- **결정:** 두 비트의 정확한 중간 시점에서 nearestBeat 호출 시 이전(낮은) 비트를 반환한다. 부동소수점 오차 흡수를 위해 1e-9초(MIDPOINT_EPS_SEC) 허용 오차를 적용한다.
- **근거:** 기획서에 중간값 판정 규칙이 없으므로, 일관된 동작을 위해 "이전 비트 선택" 규칙을 채택. EPS는 IEEE 754 배정밀도 부동소수점의 실질적 오차 범위(~1e-15)보다 충분히 크면서 판정 윈도우(60ms 이상)보다 무시할 수 있는 크기.
- **변경 조건:** 판정 로직 구현(태스크 3) 시 다른 규칙이 필요하면 재검토.

## D-05 템포 요청 시 현재 비트는 TempoSystem이 계산 (2026-11-16)
- **결정:** 템포 요청 시 현재 비트는 호출자가 넘기지 않고 TempoSystem이 nowSec(오디오 시계)에서 계산. BeatTimeline.requestTempo는 TempoSystem 전용.
- **근거:** 리뷰 #2. 호출자가 미래 비트를 넘기면 대기 중 예약을 우회할 수 있음.
- **적용:** 태스크 4에서 구현. 이번에는 코드 변경 없음.

## D-06 판정 윈도우 경계 비교 허용 오차 (2026-11-17, 승인)
- **결정:** RhythmJudge의 윈도우 비교를 `|errorMs| <= window + JUDGE_EPS_MS(1e-6ms)`로 한다.
- **근거:** 3.1 "경계값 포함(<=)"을 지키기 위함. 예: 100BPM→120BPM 전환 후 beat 8(4.8s) +75ms 입력은 부동소수점 계산 시 errorMs = 75.00000000000017이 되어, 허용 오차가 없으면 Perfect가 아닌 Good으로 판정된다. 1e-6ms = 1e-9초로 D-04(MIDPOINT_EPS_SEC)와 동일 크기이며 테스트 벡터의 1ms 간격보다 충분히 작다.
- **변경 조건:** 입력 타임스탬프 정밀도가 1e-6ms 수준의 차이를 의미 있게 구분해야 하는 경우(현실적으로 없음).
